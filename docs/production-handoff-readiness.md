# 持久交接后续：切换准备与不能跳过的门槛

本准备工作基于 #250、#251 合并后的 `a5ffd64fa987f3a64676478c05a212aa8146418a`，不是对旧 `.126` 的修改、重建或重新标记。本次只有仓库与隔离环境操作，没有连接生产、切换入口、执行真实评分或打开留存开关。

## 本批工作的边界

- [入口适配器](production-handoff-adapter.md)：核对仓库中实际入口和跨进程屏障能力。缺少能力、原始在途消息或任何原零门槛时拒绝确认切换，不能用隔离组件状态代替生产证明。
- [容量观察与停流](handoff-capacity-operations.md)：读取实际保留件的计费，而不是调用可能写盘的 `/webhook/receipt`；观察失败、容量或试运行预算到达时请求一次幂等停流。没有可信停流回执时保留 `stop_unconfirmed`，不是已经停止。
- [held 权限与审计](miniflux-held-access.md)：在合成 PostgreSQL 验证最小权限和审核／执行分离；不授权重签、重置 attempts、重构原文、改 endpoint 或自动清理。现有 held 工具仍仅用于隔离。

这些结果不等于可以直接部署。现有应用没有所有入口共用的跨进程 admission 屏障：只停止 Miniflux、拦外部 Nginx 或取得单个 release/refresh 锁，不证明冷评分、手动刷新、feedback、内部生产者及旧异步请求已停止。必要的应用屏障应作为另外的窄变更审查，不能偷偷降低本次适配器门槛。

## 容量和保留不是吞吐承诺

接收回执最多 4096 条、256 MiB，按包括别名意图与完成空间的预留计费，现有实现没有自动过期。发送 outbox 最多 5000 行、256 MiB，所有状态都计费；只有确认交接的 acked 行满七天才可由原有有界清理处理。pending/inflight/held 不自动删除。20 次发送领取和七天年龄是传输预算，不是模型调用额度。

任何有限停流试运行都要另行批准开始／结束时间、允许新增条数、采样周期、保守预留和具体操作身份。只看磁盘空闲、平均消息大小、消费速率或已经完成的任务数，不能证明仍有可接收的去重与回执容量。停流后上游未持久化的列表仍可能滑出；本方案不承诺无限期无损。

## 将来单次发布的建议顺序

1. 先审齐应用 admission 屏障、真实生产入口清单及宿主执行适配，核定所有旁路与旧异步消息的原始字节保全；未确认项必须阻塞，不用人为填写的零或布尔值通过。
2. 分别锁定接收端与固定 Miniflux 补丁的完整 SHA、镜像 digest、数据库身份和迁移；重新跑完整 CI、正式干净门禁及两款候选的联合隔离验证。旧 `.126` 保持原样，必须使用新镜像身份。
3. 发布前在另行批准的有限窗口验证实际配置、存储权限／空间、全入口停止、活动任务排空、旧契约未完成续作零门槛，以及 receipt/outbox/journal/终态证据完整。现场不符合即停止，不盲重试切换。
4. 先可靠接管接收与拒收保全，再进行经批准的单次切换；失去 ACK 只能查询同 operation 的持久回执，不把普通 202、健康 200 或客户端超时当作操作结果。
5. 保持自动回退关闭。新 outbox、回执或终态产生后，直接换回旧 sender 或 `.125`/`.126` 不安全：旧 sender 不消费 outbox、会重新启用旧异步路径，旧 receiver 不理解新完成回执。需先静止生产者消费者、独立保留原始数据和原 Compose，并另审兼容消费者或前向修复；不得删表、降 schema 或重新评分补偿。
6. 真正启用后才安排两个明确未来自然轮次及真实页面验收，分列调用／Token／未知用量、receipt 与原 outbox 的精确身份、最终信号、续作归因和容量停流结果。未自然触发路径保留未验证，不补造旧窗口。

本次不改评分／事实保护／阈值、不补跑采集、不调用真实模型，也不据隔离样本宣称全天成本、生产丢失率或物理断电耐久性得到保证。生产数据库角色、入口绑定、负载和空间均未在本次核验；不要把静态仓库清单当现场清单。
