# 自然采集评分递延的有界续作

## 边界

首轮评分被语义校验拒绝、后备请求又未取得判决时，已有保护会返回
`score_deferred`，不把固定中性直接写成第一次的最终评分。本改动不放宽
事实校验、主体/数值/单位/方向/否定保护，不改提示词、阈值或后端超时。

此前自然刷新只累计递延数；新闻离开 `max_entries` 窗口后不一定再出现。
现在仅自然刷新以 `persist_deferred=True` 保存这类原始输入。后续正常刷新
开始时先续作最多 20 个到期条目，不重新请求其 RSS，不增加 cron、线程、
即时采集重跑或后台模型轮询。第一次只由 webhook/冷请求触发的递延不
新建本日志；它们若遇到已经存在的自然续作身份，则共享该预算和原输入。

## 身份、预算与结果

- 唯一身份是 `sha256(link + NUL + strategy_version)`，不是整个任务 JSON。
  冻结原题、来源摘要、提示词正文、feed、few-shot 上下文和原发布时间；
  后来的跨源到达不能替换它们，也不持久化含凭证的完整配置。
- 已接收入日志的新闻，最多三个评分流程轮次（首轮加两次续作），不是
  最多三次物理模型请求。一轮仍可能包含多后端、二阶段和摘要调用。
  没有测量新增流量或费用，不能把每轮最多20个续作说成总调用量上限。
- 调用模型前先原子持久化已使用轮次；进程重启、租约/锁释放不赠送预算。
  同身份使用非阻塞文件锁，普通进程内同链接单飞继续保留。
  尚未有持久记录的首次多进程同时到达，仍属于原来进程内单飞的边界；
  不宣称此次解决了首次跨进程评分竞争。
- 同一次流程需要的全部模型步骤仍沿用原有规则。第三轮仍没有后备判决
  时，保留原有终态安全中性逻辑；如果第三轮预留后崩溃，且没有保存完整
  决策，则标为 `exhausted`，不擅自调用第四轮或编造评分。
- 已有持久记录的续作，其完成评分及待写快照在写库前冻结；数据库写失败后
  只补写。重启后先检查真实缓存/账本，已提交但确认丢失时不会重复调用、
  重复写信号。后续写入的首次可用时间不回填为失败时刻。尚未建立持久记录
  的首次正常评分仍沿用原有写入行为，不宣称此次覆盖了它的全部写失败恢复。
- 当前策略不再匹配或源被停用时终止旧续作，不偷偷在新契约下执行。
  24小时过期后终止；所有终态保留小型记录并移除原文/待写内容。

## 私有目录与失败语义

日志位于 `AI_FILTER_DB_PATH` 相邻的 `natural_score_continuations/`，
目录0700、文件0600；原子替换加文件及目录同步。默认最多128个活跃条目、
4096个总身份、每行256 KiB，不静默截断原始输入，不清理旧数据库/事件。
不自动删除终态记录；达到总容量后需单独审查和授权处置，不能靠自动淘汰
让旧新闻重新获得次数。锁文件同样有界。

容量满、输入超限、磁盘不可写或记录损坏都不代表已接收成功：
新闻继续 `score_deferred`，记录无原文的诊断告警。**没有成功保存的工作
无法保证跨重启续作或持久预算**；不能声称磁盘故障时也绝不会漏新闻。
普通未进入续作的业务异常保持原来的异常语义。

`score_continuations` 列出本轮续作的 attempted/completed/deferred/errors、
terminal_unscored、物理模型调用数以及剩余活跃/到期/终态数量。尚有活跃任务或续作失败时不
推进完整刷新时间。旧轮的 `partial` 不被倒写成成功；后续完整自然刷新
才可推进 `last_full_refresh`。终态 `expired/exhausted` 是未完成原因，
不是“得分低”或“事实校验通过”，也不自动恢复历史新闻。

### 待续作与终止未评分

逐条执行入口和刷新轮次见 [新闻处理与模型调用关联](news-processing-trace.md#执行来源与刷新轮次)。
开场续作与普通 feed、webhook 命中相同 journal 时按实际入口记录；
`continuation_attempt` 保留持久预算语义，不能当作物理模型调用次数。

- `score_deferred` 只表示待续作；已终止且没有可复用最终评分的身份返回
  `score_terminal_unscored`，不会重建任务、增加次数或写入虚构的中性结果。
  已有真实缓存/账本的正常复用仍优先，不会把已评分新闻误标为终止未评分。
- 当终态新闻仍在当前源列表里，源统计单列 `score_terminal_unscored`，
  刷新统计单列 `score_terminal_unscored_entries`；首页与源健康提示显示
  “终止未评分”，不计入“待评分”、`filtered_count` 或完整结果缓存。
  该源仍部分完成，`last_full_refresh` 不前进。持续降级有明确的终止原因，
  不是还会自动恢复的承诺，也不能为消除降级而把终态改成成功。
- 已滑出源列表的任务若在本轮过期、策略变化或源停用，续作批次的
  `terminal_unscored` 记录这次转为终态，保持本轮不完整。之后仅保留历史终态
  计数，不重复把同一终态计成新的待处理任务；后续轮的来源完整不表示旧任务
  曾经完成。批次计数和源列表计数不去重，不能直接相加当唯一新闻数。
- 新闻处理诊断沿用已有 `state=error`，但保留准确的
  `outcome=score_terminal_unscored`，不标 completed，也不借用其他信号。
  不改数据库表或状态约束。

### webhook 混合批次与负向回执

- 同批出现终止未评分和正常新闻时，把终态条目的索引、文章身份哈希、
  策略、结果与记录时间写进原任务信封的 `terminal_unscored`；该记录与
  下一条游标一次原子替换，完成文件同步及严格目录同步后才处理后续条目。
  写入/同步失败不跳过该条。原任务正文和摘要身份不变，审计行不另存原文。
- 终态不增加通过数或过滤数，不再消耗模型轮次。任务重启恢复游标及
  终态记录；后续条目已写库但确认丢失时按已有缓存/账本复用，不重复打分。
  后续条目如仍递延，沿用自己的次数，不继承前条或获得额外次数。
- 正常条目处理完后，整批返回 `webhook_terminal_unscored`，源健康明确
  “终止未评分”，不写成功回执；任务立即归档到既有死信目录，保留逐条
  结果与最终游标。同任务重复交付沿用原摘要去重，不能重新获得尝试预算。
  全部是终态的批次也按此处理；缺少持久任务上下文时失败，不直接略过。
- 最终归档先在活跃信封严格持久化归档意图，冻结来源目录、最终结果与
  内容哈希；目标使用任务摘要和已有尝试次数确定的固定文件名。先原子
  写入目标、同步文件及目标目录，确认负向回执可靠保存后，才删除活跃
  文件并严格同步来源目录。任何同步错误都不能返回归档成功。
  目标已出现但未确认时，两份记录共同维持原摘要去重；重启优先补归档，
  不再领取评分、不增加任务或模型次数。目标已有时只接受相同冻结内容，
  冲突记录均保留；本任务已有目标不占新的死信容量。来源删除后的同步
  失败通过目标中保留的意图恢复，不能反向创建可评分任务。最后在同目录
  将待确认档改为已确认文件名并严格同步；该步失败仍报告收尾未确认。
  恢复只读取待确认文件名，已确认档不在每次领取时重新读取原文。
- 死信目录沿用既有容量（默认256项），终态负向回执不被自动淘汰。
  目标尚未可靠保存或死信满额时保留活跃信封及检查点，且不妨碍其他
  已接收的正常任务被领取。达到任务最大次数后仅尝试归档，不执行条目。
  普通失败档仍沿用原有淘汰规则，但不能淘汰终态档或刚写入的新档；
  若容量全被终态档占用，也保留普通失败任务，避免去重身份丢失后重获预算。
  保留项会占活跃容量，最终可能阻止新任务接收；告警需要单独审查处置，
  本改动不自动删除证据，也不声称磁盘故障下仍能无限接收工作。
  已耗尽任务的归档失败按进程内60秒退避，最多记128个路径，不每秒打印
  堆栈；重启可重新尝试归档，但不重置持久的任务或评分次数。
- 原有默认5次任务尝试、每条4次传输递延，以及自然续作最多3个评分流程
  轮次均未增加。归档恢复不是再次调用模型；后续正常新闻恢复处理本身
  会产生此前被阻塞的合法调用，不能承诺新增调用量为零。

### 回退前置条件

`.123` 能读取原任务结构，但不认识新增的终态回执：若直接把仍活跃的
混合信封交给旧版，旧版可能沿游标继续后写成成功回执。因此仅“能读JSON”
不等于回退语义兼容。发布前及需要回退时必须核对 pending/inflight 中无
带 `terminal_unscored` 的活跃信封；若有，先停止回退并另行决定有审计的
隔离/处置方式，不能删除或重置这些条目来绕过检查。已归档的终态批次在
旧版中仍能按任务摘要阻止重复交付，但旧版的死信淘汰策略不保护这些档案，
需在回退前独立保全所有终态档案。数据库结构不变不代表队列回退没有限制。

## 测试与发布

回归使用合成 RSS、临时 SQLite 和假模型传输，覆盖滑出前5、真实两轮刷新、
跨入口并发、重启、后备恢复、预算耗尽、失败写入恢复、队列满再接收、
策略变化、过期、坏记录及容量边界。没有调用真实模型或复制生产库。

`core/processor.py` 会变化；两个新增评分续作模块也纳入评分代码指纹。
因此后续发布会改变策略契约，可能让再次采集到的旧链接重评。历史数据不
重算、不回填；映射代码未改。合并与部署仍需单独批准，并重新核验最终镜像。
