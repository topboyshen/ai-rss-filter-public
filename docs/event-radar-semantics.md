# 事件雷达语义与评估口径（P0）

事件雷达回答四个问题：**发生了什么、证据来自哪里、哪些公司有支持、后续市场结果是否成熟。**
它不是荐股、预测或方向判断工具。本文固定页面状态、API 字段与人工评估标签的共同定义；
任何改变状态语义的实现，必须同时更新本文与对应测试。

## 一、四个维度

### 1. 事件主张（claim）

事件卡展示的是**冻结来源实际说了什么**，不是系统推断出的结论。

| 项 | 定义 | 现有字段 |
|---|---|---|
| 事件标题 | 合并后事件的代表性主张 | `events.title`、API `event.title` |
| 来源主张 | 单条来源的原文主张 | `event_evidence.claim_text`、`excerpt`、`snapshot_text` |
| 合并关系 | 哪些事件被合入、何时、为什么 | `events.merge_state` / `merged_into`、`event_merge_history`、API `event.merge_state` |
| 来源数量 | 当前事件的来源与截断状态 | API `source_count` / `sources_truncated` |

硬规则：**合并后的事件不得把一个来源的说法显示成所有来源共同确认。** 来源主张、立场与
发布方分组必须逐条保留；转载谱系只能折叠完全相同的冻结快照，不能据此认定发布方独立。

### 2. 证据状态（evidence）

| 状态 | 判定 | 页面文案 | DB / API |
|---|---|---|---|
| 支持 | 来源明确支持事件主张 | 支持记录 | `event_evidence.stance='supports'` |
| 否认 | 来源明确否认或更正 | 否认记录 | `stance='contradicts'` |
| 背景 | 仅提供背景、计划或请求，未确认发生 | 背景记录 | `stance='context'` |
| 未核实 | 无来源证据，或映射回放失败/未匹配 | 证据不足 | 无 evidence 行；`event_mapping_replay_ledger.status in ('no_match','failed')` |

聚合口径（影子证据拓扑，不参与评分/映射）：单方支持、规则判定多发布方支持、支持与反驳并存、
仅反驳、仅背景。**证据覆盖不等于映射正确**；覆盖只能说明当时存在支持材料。

**请求/计划与已完成**目前共用 `context`，没有独立枚举。人工评估必须单独记录这个区别；
是否增加枚举属于 P4 候选，不在本轮改。

#### 2.1 阶段标签（页面展示）

页面在来源主张旁显示阶段标签。标签只来自冻结的 `claim_text`，不读取模型输出，也不改写
`stance` 或数据库枚举。

| 标签 | 页面文案 | 判定 |
|---|---|---|
| `planned` | 计划（未完成） | 未否定的计划、拟议、接近、寻求，或“将纳入/将形成/将完成”等未来式 |
| `completed` | 已完成表述 | 未否定的完成、签署、获批、并网、裁定、起诉、纳入、增至、形成等 |
| `neither` | 观点/背景 | 观点、建议、预测、判断，或“摩根大通：/高盛：”等具名机构观点前缀 |
| `negated` | 否认/澄清 | 计划或拟议被“暂无/没有/否认/尚未”等否定 |
| `not_completed` | 未完成/未发生 | 完成、签署、获批等被“尚未/未/未能/无法”等否定 |
| `unknown` | 空 | 没有明确阶段标记，或 claim 不属于阶段适用范围；不猜测 |

判定按子句顺序进行：先看每个子句中的未否定标记；同一子句的计划与完成同时出现时，保留
“计划（未完成）”；混合标题由第一个含未否定阶段的子句决定。例如“法庭作出裁定，公司拟上诉”
归为 `completed`，不因后面的“拟”改判为计划。否定范围只限当前子句，不跨标点或“但/然而/不过”
等转折连接词吞掉后续断言。

#### 2.2 阶段标签适用范围（v1）

阶段标签只描述**可发生/未发生的事件动作**当前处于什么阶段；它不描述行情方向、数据读数、
观点强度或新闻价值。标注和验收先分 `scope`，再谈 `phase`。

| `scope` | 含义 | 页面期望 |
|---|---|---|
| `event_action` | 有明确主体和可计划/完成/否认的事件动作 | 显示 planned / completed / negated / not_completed |
| `event_opinion` | 明确针对事件/公司的观点、预测、背景、目标价/评级 | 显示 neither |
| `out_of_scope` | 行情、价格、数据、摘要、无事件动作的泛评论 | 不显示阶段；空白/unknown 为正确 |
| `undecidable` | 主体/动作不清或信息不足 | 不显示阶段；空白/unknown 为正确 |

关键区别：

- 对 `out_of_scope` 和 `undecidable`，系统显示空白是**正确**，不是阶段覆盖失败。
- 对 `event_action` 和 `event_opinion`，系统显示空白才是覆盖失败。
- 对 `out_of_scope`，系统强行显示 planned/completed/neither 是误标。
- 行情、价格、指数、收益率、汇率、商品、拍卖/持仓/概率/数据、早报/盘前/汇总/直播/日历
  均不属于 `event_action`；分析师目标价/评级调整属于 `event_opinion`，不按 `completed`。
- 标题同时包含行情和事件动作时，按事件动作判定，行情分句忽略。

`scope` 目前是标注/验收字段，尚未进入页面 API；页面仍只显示 `phase`/`phase_label`。
不要为 `out_of_scope` 或 `undecidable` 造阶段标签。

报告必须分开给：

| 指标 | 分母 |
|---|---|
| `event_action` 阶段覆盖/准确 | 所有 `event_action` |
| `event_opinion` 的 `neither` 覆盖 | 所有 `event_opinion` |
| `out_of_scope` 的“无阶段”正确率 | 所有 `out_of_scope` |
| `undecidable` 的“无阶段”正确率 | 所有 `undecidable` |

R01–R20 和早期 H/P 样本的冻结标签不回头改写；新样本先标 `scope`，再标 `phase`。四类不得
混成一个准确率。

### 3. 公司映射（mapping）

| 状态 | 判定 | 现有字段 |
|---|---|---|
| 直接提及 | 来源标题/正文点名公司，且有支持性原文 | `event_securities.relation_type in ('direct','direct_impact','affected')` 且 `event_evidence.mapping_id` 非空 |
| 规则映射 | 主题/概念池映射，无逐条原文支持 | `relation_type='concept'` 或映射无 evidence 行 |
| 证据支持 | 上下游/生态关系且有证据 | `upstream` / `downstream` / `ecosystem` + evidence |
| 未知 | 无可验证映射 | 无 mapping 行；`event_securities.is_current=0` 的历史映射不算当前证据 |

`benchmark_proxy` 不是公司映射，不进入个股展示。置信度、相关度、映射理由与版本分别为
`confidence`、`relevance`、`rationale`、`mapping_version`；页面标注“历史映射”时不得当作当前证据。

### 4. 市场结果（outcome）

| 状态 | 判定 | 页面文案 | DB / API |
|---|---|---|---|
| 未到期 | 目标交易日尚未到达 | 尚未到期 | `observation_state='not_due'` |
| 缺个股收盘 | 目标日缺少证券收盘 | 缺少个股/证券收盘价 | `missing_asset_close` |
| 缺基准收盘 | 目标日缺少沪深300收盘 | 缺少沪深300收盘价 | `missing_benchmark_close` |
| 已完整 | 个股与基准收盘均冻结 | 收盘字段完整 | `complete`（`data_status='complete_close_only'`） |
| 旧记录未知 | 旧契约或方法不支持 | 旧记录状态未知 | `legacy_unknown` |

结果冻结口径：`horizon`、`baseline_at`、`measured_at`、`baseline_price`、标的证券、
基准证券、`method_version`、`data_version`、`revision`。**缺失不估算、不前向填充、不改写历史结果。**
可交易性单独标注：完整日线、涨跌停收盘、停牌、缺开盘价、历史未知；回测收益不等于可实现收益。

## 二、完成标准（P0）

1. 页面文案、API 字段与人工标签使用同一套状态名；不允许页面自造同义词。
2. **事件重要**不推出**公司受益**，也不推出**股价方向**。
3. **证据覆盖**不推出**映射准确率**；**回测收益**不推出**可实现收益**。
4. 任何状态缺失都显示“未知/不足”，不用摘要、相似事件或收益补造证据。

## 三、后续（P1–P4）

- **P1 端到端追踪**：固定小批样本，覆盖多源重复、合并、否认/更正、计划/已完成、直接提及/主题映射、
  未到期/缺收盘；记录原始标题→成员与合并→映射依据→页面卡片→冻结结果每一步的 ID、时间、版本。
- **P2 页面验收**：列表、详情、日报、周报、首页摘要分别验收截断、缺来源、超时、日期/分页、
  结果状态、基准/目标日/版本，以及桌面/窄屏/真实浏览器。
- **P3 人工诊断集**：分别标注同一事件、合并正确性、来源是否支持卡片描述、公司是否直接提及、
  映射证据方向、结果可判定性及不可判定原因；报告分母、分歧与不可判数。
- **P4 单变量修复**：等诊断集指出最常见且可复现的一类错误，只改事件合并、证据呈现、公司映射
  或结果状态中的一个变量，保留旧样本作回归。

## 四、非目标

本轮不扩大采集、不加入新模型判断、不增加方向分或“成功事件”收益门槛；这些都会增加新变量，
而基础证据是否正确尚未验收。
