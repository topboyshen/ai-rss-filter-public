# 受控生产发布适配

本入口连接经审定的私有构建契约、实际锁、关闭启动、网关、发送端和发布登记。
它不建立空回执库，不把历史未知原文算作已保全，也不替代现场盘点、正式门禁或实际旧镜像兼容性核验。

## 输入与首次接管

`python -I -B scripts/controlled_production_release.py execute --plan /绝对私有路径/plan.json`
只接受精确字段的私有计划；每份附属输入均绑定原始文件 SHA256，源码须为干净的最终提交。
计划包含 migration、finalize、admission_policy、sender、legacy、gateway 的独立绑定，以及不重叠的运行/状态/迁移/生命周期/证据目录。
附属文件和目录不可通过链接、换 inode 或目录别名代替。

首次接管需先完成并保留旧入口停流的原始操作，以及实际发送端的首次 CLOSED 初始化：

- `production_legacy_takeover.py` 持有已登记 root cron writer 的真实锁，保留完整 cron 原件。
  仅对已绑定旧容器发送一次 TERM，有界等待自然退出，不自动 KILL、重启或回退。
  这是已登记 writer 的协作约束，不能防止任意 root 绕过约定修改 crontab。
- 旧版未保存的异步原文仍为未知；不能从现有文章表重造签名批次，也不补发。
  已知队列、held、legacy 原件和未完成续作仍执行原有门槛，未知不当作零。
- 新发送端必须使用独立核验的新镜像，实际 PG 身份、schema135 和首次 CLOSED 原始回执须匹配。
  应用入口不会调用 initializer 或以普通202代替可靠落盘。
  独立的 [发送端首次接管适配器](production-sender-bootstrap.md) 在旧入口已停后逐步执行
  create、实际二进制核验、exact-ID start、首次 CLOSED 与原操作查询；已有控制历史不能重置。
- 原 `.125` 镜像、原 Compose、旧容器以及终态/held/原文证据均保留。
  这不等于可直接安全回退；停生产者消费者、保存 journal/负收据和独立库存核验仍是回退前置。
  `.126` 不参与构建、改写或重新标记。

本入口在迁移前再次要求真实 legacy 能力的 `check_stopped()`，不能用调用方 JSON 声称已排空。
旧入口适配器的 `inventory_drained=false` 不会被发布入口改写成已排空；M1 自行执行已知库存门槛。
若旧发送端不在同一宿主、存在未绑定入口或脱离已核 cron 进程树的活动，不能直接采用单宿主计划。

## 单次发布顺序

1. 保持同一把真实 release flock，正式 `controlled-check` 核最终源码、私有配置、镜像、完整构建凭证、旧发布登记和 mapping 门槛。
2. 保持 legacy writer 锁并独立确认旧运行已停；查原首次 CLOSED 操作，不重发初始化。
3. 实际 M1、精确候选 create/grant/start、关闭初始化、arm；候选只允许两应用服务，旧容器 ID 必须保留。
4. 在业务仍关闭时 prepare/confirm，再单独切换固定镜像网关。网关使用独立 project，不能通过放宽“两候选”约束混入应用生命周期。
5. 先启动预开启守护进程，核真实 PID/boot/starttime 和新鲜 pulse；之后才允许接收端与发送端恢复。
6. 建立有限续签授权和首份实际 lease，准备持续监督，执行真实健康与 sender 复核并一次登记。
7. 释放发布锁后由同一守护进程接管监督；核真实 live tick 后才写最终 `deployed_controlled`。

可查询的原操作与新操作明确区分。ACK 未知不重发 create/start/resume，不换 operation、标签或预算。
`query` 只沿原登记 journal 确认原字节过渡，不恢复业务或发新 lease。
若发布已 STOP，历史登记成功也不会被描述为当前业务正常。

## 挂载与控制目录

原业务数据 bind 不替换。仅显式审定的 state/fence 子目录可留在原 `/app/data` 内；目录全链绑定设备、inode、UID/GID、权限和相对路径。
控制目录0700，同设备，不跟随 symlink，拒绝路径越界、遮蔽与可写授权/配置别名。
数据库、私有配置和只读 grant 仍走原有精确检查；端口、网络及逐角色业务挂载规则不变。

主发布进程和独立守护进程都从同一封存环境加载实际配置，并核有效配置哈希。
不会继承调用方任意环境变量；正式门禁的证明目录和原健康超时、轮询配置单独保留并再次校验。

## 有限运行与失败边界

授权、每份 lease、续签次数、累计原件/字节和现存容量都有硬上限；续签不重置 generation、原 operation 或累计配额。
接近容量、时钟/进程身份变化或监督失败时，对发送端和接收端分别执行真实停新，保留每项未知。
`producers_stopped_drain_pending` 仅表示停新已确认，不表示任务已排空、容器已暂停或历史原文完整。

Go 的 OPEN 不会因宿主监督进程消失而自行到期。接收端会因守护 pulse/lease 到期拒新，发送端保留有界原件；不能把这种状态报告为双方已经停流。
生产必须审定有限期限、容量预警和监督进程恢复/终止处置，不能靠延长配置获得永久运行声明。
任何失败保持原始 STOP 与原件，关闭自动回退，不补采集、不调用模型补证。

## 证据与验收

本地单元测试、合成 inspect 和实际原生 Docker/PG 证据分别记录，彼此不替代。
原生测试中的临时 loopback 桥仅转交到真实隔离 Go/PG，不算生产 namespace 证明；
固定 `nsenter` 传输另用独立原生步骤核验。失败时先尝试原操作停新，并在关闭临时桥前
有界等待原守护进程退出；未确认的退出保持未确认，不以强杀替代。
托管完整 CI、正式 Linux 干净工作区门禁、候选镜像内容与实际 `.125` 的合成库兼容性，以及现场精确入口/库存均须各自通过。
原生隔离维持应用/发送端768MiB、256PID和原PG上限，不复制生产数据库。
部署后做独立 verify、真实页面和明确未来的自然采集窗口；启动快照和普通200不作为自然通过。
