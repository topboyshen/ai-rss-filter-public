# 完整切换的私有宿主隔离验证

本验证只在 GitHub 托管的 Linux amd64 合成环境运行，不是生产部署入口。
独立 `isolated-host-ingress` 成功不能替代完整 `native-amd64` 成功。
完整证明必须经过原有关闭初始化、迁移、实际网关切换、监督和收发路径。

## 拓扑与镜像身份

完整流程使用新建的 network/mount namespace、独立 Docker daemon 和唯一的
自有 bridge。该 bridge 的实际发布端口必须供同一私有宿主的 loopback HTTP
访问。私有宿主不能有默认路由、外部接口或外部 DNS；原有实际端口、HTTP、
进程身份及资源检查继续执行。不能用申请端口、容器 IP 或容器内 HTTP 替代。

旧的 internal-network 默认验证路径仍保留。普通 bridge 只有在私有宿主的
冻结上下文、存活进程、socket 对端及网络身份全部通过核对时才能使用。
上下文缺失、被改写或所属进程退出，必须拒绝。

固定 Python、PostgreSQL、Redis、nginx 依赖先在外层取得原始 manifest 和 blob，
逐项验证完整 digest、长度和平台。内层镜像服务仅在私有 loopback 提供这些
已验证对象的 GET/HEAD，不代理请求、不取得新内容。私有 daemon 再按原始
固定引用实际 pull，继续检查真实 RepoDigests、image ID、Config 和 RootFS。
`docker save/load` 不用作依赖 RepoDigest 的替代证明。

新发送端和候选应用镜像按完整 image ID、源码及配置标签核验。应用构建仅接受
一次绑定既定路径、源码身份和已封存合同的请求，由外层执行原构建函数；内层
不因此获得外部 Docker socket 或联网权限。失败与不明回执都保留原件，不再
提交同一构建请求。

## 资源与时间

应用各实例保持 768 MiB／256 PID，PostgreSQL 保持 384 MiB／64 PID，其余原
组件限额不变。宿主监督进程和私有 daemon 另有自己的受限 cgroup；不能把这
个限额称为完整容器组的总内存限额。实际运行时须核对进程所在组和容器限额。

完整入口共享进入时建立的 600 秒绝对截止时间。下载、构建、探针、交接、
执行及最终证据整理均消耗该预算，阶段切换不重置；完整 CI job 仍为 15 分钟。
同步 DNS 或客户端超时不证明远端操作已撤销。操作结果不明、状态不完整或
日志保全失败时必须停止判定成功；空的运行容器列表不能消除先前不明操作。

## 证据布局

通用证据准备器使用可完整还原的 canonical JSONL 清单，字段表只保存一次，
每项保留完整路径、类型、文件身份和链接目标。清单实际编码字节仍最多 8 MiB，
路径索引、条目数、逻辑文件大小、最终报告和 300 秒期限分别受原有或更窄限制。
不删除失败记录，不跟随链接，不通过减少身份字段绕过源和输出复核。

`metadata_bound` 的诊断区分源清点、源复核和输出复核，公开摘要只含固定阶段、
预算和路径哈希。8 MiB 是清单元数据限制，不是整个 artifact 的大小限制。
即使上传步骤成功，只要准备器输出 STOP，就不能称原件归档完整。

私有宿主的原件继续保留在 root 私有目录。公开安全包中的 `complete` 只说明
指定的脱敏材料完整；`full_raw_archive_verified=false` 明确保留全原件导出与
核验缺口。镜像层、daemon 存储和超过安全包边界的原文不塞进小摘要包。

## 判断通过

合成回归、主测试、独立小入口和完整切换分别记录结果。必须使用同一最终
提交的完整 CI 证据。任何入口守卫拒绝、原完整流程失败、未知操作、清理不明
或必要证据缺失，都不能由其他成功项覆盖。历史失败、STOP 和归档缺口保留，
不能用本次成功反推旧现场已成功。
