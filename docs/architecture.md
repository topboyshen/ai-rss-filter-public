# 架构说明

本文说明系统由哪些部分组成，以及各部分不做什么。
发布步骤见[部署说明](deployment.md)。
发布合同见[部署、迁移与恢复](deployment-and-recovery.md)。

## 1. 系统做什么

系统读取财经来源。
系统给每条新闻一个阅读优先级。
系统保存来源、评分路径和评分契约。
系统展示新闻、简报、事件和历史旁证。

系统不执行交易。
分数不是投资结论。
容器健康不证明评分正确。

## 2. 运行部分

生产拓扑有五个常驻服务。

| 服务 | 作用 |
|---|---|
| `ai-filter-api` | 接收 HTTP 请求。页面请求不运行完整采集。 |
| `ai-filter-worker` | 刷新来源、续作评分，并发布页面快照。 |
| `ai-filter-web` | Nginx 网关。它把本机端口转到 API。它没有应用修订号。 |
| `redis` | 保存短期共享状态。它不是评分账本。 |
| `rsshub` | 提供部分来源。 |

三个任务按计划运行。它们不常驻。

| 任务 | 作用 |
|---|---|
| `market-close-collector` | 写收盘收据。 |
| `event-enrichment` | 增强事件映射。 |
| `security-master-sync` | 同步证券主档。 |

页面请求不启动这些任务。

## 3. 一条新闻怎么进入页面

1. 来源进入系统。来源可以是 RSS、RSSHub 或 Webhook。
2. 系统规范化标题和链接，并去掉重复项。
3. 本地规则可以放行、拒绝，或把条目交给模型。
4. 模型按当前评分契约打分。校验拒绝时，系统可以写入保守中性。
5. 系统把结果写入 SQLite。缓存命中不伪造一次新的模型调用。
6. Worker 发布页面快照。默认页面读取最近一次成功快照。

保守中性是处理结果。它不表示新闻不重要。
标题缺失只表示标题缺失。它不表示正文不存在。
评分时的正文范围没有记录时，页面写“未记录”。
卡片上的评分路径是缓存处理路径。它不证明每个字段的生成来源。

## 4. 数据放在哪里

SQLite 文件是 `data/cache.db`。
API、Worker 和计划任务共用这个数据目录。
同一时间只有一个写入协调者。停止一个容器不等于没有写入者。

收盘结果在 `data/market_close`。
收盘成功不证明新闻刷新成功。
新闻刷新成功不证明收盘成功。

发布记录在 `data/releases`。
应用容器只读挂载这层记录。

## 5. 公开代码和生产运行版本

公开仓库提供可审查的代码。
生产运行的是已发布镜像。
公开主线前进不表示生产已切换。
CI 成功不表示生产已发布。

## 6. 这些词不要混用

| 词 | 意思 |
|---|---|
| 健康 | 容器健康检查通过。 |
| 采集完整 | 最近一次新闻刷新没有未完成来源，且续作队列不是未知。 |
| 评分质量 | 人工标签和后验门槛。它不是健康，也不是调用成功率。 |
| 镜像回退 | 换回 `previous` 镜像和当时的 Compose 清单。 |
| 数据恢复 | 恢复 SQLite。镜像回退不做这件事。 |
