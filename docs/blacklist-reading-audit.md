# 黑名单漏读核查：只读重放，不修改策略

黑名单在原始标题清洗后、缓存／相似稿／模型评分之前执行。命中直接返回
`blacklist`，不新写新闻缓存、信号或事件；逐源处理只累计 `blacklist_hits`。
因此，数据库里找不到新闻不能独立证明它因黑名单漏读，也不能证明没有采集过。

现有策略不区分关键词的否定和重要性。例如，配置含 `业绩预告`、`股东减持`
和 `减持` 时，以下标题都会阻断，且不会进入评分：

- 业绩预告：预计净利润同比下降80%
- 澄清：不存在股东减持安排
- 股东减持计划公告

前两条值得人工检查，并不意味着第三条必定不重要。本次不删关键词、不放宽
策略、不改变生产配置，也不把“未命中黑名单”说成“会进入首页”。

## 离线工具

`python -m ops.audit_blacklist_titles < samples.json` 只读标准输入并向标准输出
打印报告，不读取配置、环境密钥或数据库，不联网、不调用模型、不写入文件。
输入必须是一个显式的、小范围原始来源样本清单，不能直接传完整配置文件。
最多 100 条样本、200 条正则、256 KiB 输入。正则必须来自可信的实际配置，
不能使用外部用户任意提供的正则。命中逻辑与现有策略一样使用正则并集。

```json
{
  "schema": 1,
  "blacklist": ["业绩预告", "股东减持", "减持"],
  "samples": [{
    "sample_id": "example-1",
    "title": "澄清：不存在股东减持安排",
    "summary": "",
    "link": "https://example.com/source",
    "feed_name": "示例来源",
    "observed_at": "2026-10-10T12:00:00Z",
    "ingestion_scope": "operator_example",
    "within_processing_limit": null,
    "cache_present": false,
    "signal_present": false
  }]
}
```

`title` 必填，其余样本字段可省略；省略 `summary` 时报告会注明没有检查来源
摘要。`ingestion_scope` 只允许 `operator_example`（人工提供的例子）、
`observed_feed`（实际看见的源条目）或 `stored_original_evidence`（已存档的
原始标题证据），均不等于“已确认本轮 worker 处理／拒绝”。存档来源不伪装成
刚抓到的 feed；当前策略重放也不能逆推出该条历史入库时使用的配置。
`within_processing_limit`、`cache_present`、`signal_present` 只承接查询证据，
布尔或 `null`，工具不代查、不补全、不据此推断因果。

输出给出清洗后标题、实际正则并集的命中片段与位置，以及所有重叠规则的
独立命中片段。独立规则顺序不是实际匹配优先级。`blacklist` 表示按提供的
配置重放会阻断；人工复核标志不是重要性评分，也不是自动修改建议。

## 对一条真实漏读新闻的核对顺序

1. 记录发布方原始标题、链接、来源和观测时间，不用模型摘要代替原文。
2. 核对该条是否落在实际抓取时段和每源 `max_entries` 范围内；源列表存在
   但超出处理上限，只能说明它未进入该轮候选。
3. 用当时配置重放标题，列出具体规则；没有历史配置只能描述当前策略行为。
4. 只读检查相同链接的新闻缓存／信号与策略版本。旧缓存存在仍可能被前置
   黑名单阻断；空缺也可能由抓取、限额、解码或其他流程造成。
5. 未命中黑名单时，继续逐条定位去重、评分、门槛、页面时间窗和配额。
6. 人工区分例行通知、重大变化及澄清，保留链接与证据，再单独决定窄修。

这份诊断不重评历史记录，也不证明黑名单造成了多少条线上漏读。若后续需要
逐条生产过滤日志，须另行确定留存范围与隐私边界，不能把本次离线重放当作
已有的历史审计日志。
