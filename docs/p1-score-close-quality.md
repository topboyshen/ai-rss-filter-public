# P1：评分可用性与严格收盘修复

此变更集中交付必要修复，不调分数/通知阈值、不混合历史契约、不重打历史评分。
模型质量与研究门槛仍以 [model-quality.md](model-quality.md) 为准。

## 四个观测层（2h / 24h，当前精确评分契约）

认证接口 `GET /score-quality` 返回诊断 JSON；原认证 `/metrics` 同时输出窗口 gauge。

| 层 | 分母与分子 | 指标 |
| --- | --- | --- |
| 接口 | 实际评分模型请求 / 传输成功请求 | `ai_filter_score_transport_attempts`、`..._succeeded` |
| 格式 | 返回内容校验尝试 / 契约通过 | `ai_filter_score_validation_observed`、`..._contract_valid` |
| 事实 | 格式通过的校验尝试 / 来源锚定通过 | `..._grounding_observed`、`..._source_grounded` |
| 最终 | 模型处理的 base 账本决策 / 正常 llm、stage2 决策 | `ai_filter_score_final_model_processed`、`..._usable`、`..._usable_ratio` |

前三层按 backend/model/stage 分类；校验额外区分 initial/repair/reason。所有时序指标标明
`strategy_version` 与 `window`，不能跨版本汇总为当前队列。传输记录可能包含 SDK 重试，
校验尝试包含修复，最终账本还可能复用评分缓存；它们不是同一分母，也不是独立事件数。
最终层仅计 `signal_stage=base` 且 `is_similarity_copy=0`，排除本地拒收与 FastPass；
模型异常的 `fallback_local`/`parse_error` 纳入最终不可用分母。事件雷达修订不重复计数。

`score_validation_logs` 为新增观测表；只存有界标签，不存标题、原文或模型原始回复。
旧请求不补造校验结果；格式失败时事实校验为 NULL，未观测比例不冒充零或成功。
记录失败不影响评分决策。诊断随既有清理流程保留七天；GET 只读，不进行评分或后验重算。

`ai_filter_score_safe_neutral_warning=1` 表示窗口内至少 50 次模型处理决策、保守中性比例
至少 10%。这只是运维观察告警，不影响 health/readiness、入选门槛或模型研究资格。
Prometheus 的抓取与告警转发仍须在发布后配置；新增 gauge 不是已发出的通知。

Qwen 输出先由相同严格契约约束，明确要求 sentiment 使用中文枚举；不把英文、emoji、
未识别枚举猜成看多/看空。用 `invalid_score_contract:invalid_sentiment` 等原因观察真实
兼容性。没有调用在线模型验证新提示词，也不声称已经降低生产 27.4% 的保守中性比例。

## 理由事实与主题校验

- 数字理由复用既有数字事实上下文检查：主体、单位、同比/环比、否定与计划/已完成关系。
  支持精确的万元/亿元/万亿元换算、全半角归一化；不做近似数值容差或 Decimal 精度舍入。
  明确的发言人前缀可在替代来源视图中移除，正确引用“6000亿元”可以通过；否认、计划、
  普通公司主题前缀不删除，也不追加重复数值证据来绕过一对一匹配。
- 真实案例“超过6000亿元”不得变成“超过6001亿元”；初次与修复输出、两阶段均检查。
  失败仍走安全中性或既有后端降级，不放松既有校验来提高表面成功率。
- 常见字面事件表述增加主体/否定/计划状态冲突检测，例如未签合同不能写成已签、甲公司
  订单不能改称乙公司订单。规则不等于完整自然语言事实验证，不保证识别所有改写与隐含关系。
- 仅低分（≤4）且中性的理由允许“不涉及AI或算力”式明确否定列表豁免；肯定主题标签不能
  借此通过，来源中的主题否定不能成为肯定锚点，后续转折中的肯定语句仍检查。
- 数字理由优先引用原文完整短句，与解释分句书写。过度改写仍可能保守拒收，须继续做
  分层人工标注与影子验证；当前自动回归集不冒充 200–500 条人工 gold 集或准确率评估。
  未标注分层候选与标注协议见 [score-gold-set.md](score-gold-set.md)。
- 严格等于 `SAFE_NEUTRAL_CONTRACT_VALUES` 的固定安全中性结果跳过普通事实复述检查。
  它不是来源复述，不能因为理由里有“投资”等字或来源另有数字而被判失败。近似中性句、
  改写或夹带新数字仍走原规则。这不放宽模型高分结果。
- 事实/主题校验的来源只用原始标题和摘要。带 `[⭐分数]` 前缀或 `💡理由` 后缀的展示标题
  会先剥掉再核对，避免模型自己的错误理由给自己当证据。计划/预计/拟议不能写成已发生。

## 收盘来源

腾讯精确日线继续优先；新浪带时间戳的小时线作为 SH/SZ/BJ 第二来源。只接受服务端真实
`15:00:00` 记录，精确日期、有限正价、源时间不晚于当前时点。涨跌基准还要求已有的上一个
配置交易日真实收盘，不能跳过缺失交易日。小时 OHLC/成交量不冒充日线字段，交易状态 unknown。

新浪仅带日期的 `scale=240` 日 K 不用作严格收盘证据，不能人工加 15:00。网络请求限制代码数、
响应长度、超时、重定向及历史窗口（240 根小时线）；超出窗口继续缺失。来源失败由采集器
在原总预算内处理；无价、不支持代码、盘前价、非正价不证明停牌或未上市，不静默移出缺口。
此行为也撤回基线提交 3769af3 的“空日 K/盘前数据可排除”假设。

新增适配器不等于生产缺口已经修复。正式补价必须继续经过原写入/行情修订/结果结算路径，
保持精确端点和历史留痕，不能用后一日价格代替，更不能替缺失记录编造价格。
