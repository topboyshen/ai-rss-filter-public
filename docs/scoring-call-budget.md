# 评分调用链与 Token 记账

## 评分语义失败不再付费复制固定结果

stage1 / stage2 都先请求当前路由中的健康后端，沿用原有 JSON 契约和来源事实校验。
初次结果校验失败时，下一个后端仍获得一次独立评分机会；不将失败输出反馈给备用模型，
也不先将有价值的新闻压成中性。有效备用结果保留该后端身份，照常进入既有筛选流程。

显式启用 `llm_semantic_repair.enabled` 时，如果没有后端返回有效评分，且至少一次出现
语义/格式拒绝，本地直接生成既有固定安全中性四字段。它使用 `local_safe_neutral` 身份、
`safe_neutral_contract` 或 `safe_neutral_grounding` 路径及最后一次语义拒绝的有界原因。
这是程序保守处理，不是模型评分、推荐或独立事实证据。保守结果仍禁止提分、入选、
相似稿复用、通知与正式信号导出，并能写入隔离的缓存/账本。

开关关闭时保留原有后端尝试与 `fallback_local` 行为；全部为传输失败时也沿用该降级。

### 语义拒绝后备用后端“没给结论”：可重试，不是终态

若至少一次语义/格式拒绝之后，另有后端因超时、API/连接错误、限流等待或其他传输类异常
而**没有给出结论**，结果仍是同一组固定安全中性四字段，但带 `transport_unverdicted`
标记，并且：

- 不写入评分运行时缓存（`llm_score_cache`），重试能真正再次到达备用后端；
- 处理器在任何写入（news_cache、回测账本、证据）之前抛出 `ScoringTransportRetryable`，
  同一策略版本下同一链接最多额外重评 `TRANSPORT_RETRY_MAX = 2` 次；第 3 轮仍无结论时，
  按原设计把安全中性作为终态落库，此后按缓存复用，不再付费；
- webhook 收件队列把该条目延后重试（60/120/240/300 秒），不消耗 attempts，
  **每个条目游标**最多 4 次；超出后回到普通 attempts 计数。计数随游标写入队列文件，
  只有真实完成并推进游标才清除；陈旧进度回调不能续发额度。批内前面已完成的条目不重做；
- 定时刷新路径将该条目计入 `score_deferred`，不算过滤或 entry_errors；下次自然刷新
  若源里仍有它再评。该源记为部分完成，不推进完整刷新时间，也不缓存为完整 RSS。
  冷 `/filter`、`/filter/multi` 同样返回 partial 和 no-store，不将部分结果写入完整缓存。
  已落库子集的 DB 降级也不证明源已处理完整：保持 partial/no-store，不触发补抓或评分；
  只有完整源缓存或完整冷处理才可提供 complete。下一次自然完整刷新可重新提供完整 XML。

第 3 轮仍无结论时，先冻结终态及其评分时间、证据和元数据，再尝试提交；若 SQLite 写入失败，
后续重试只提交冻结结果，不重新调用模型。成功提交（或发现同契约已存在的记录）后才释放额度；
可用时间使用成功提交这一轮的时间，不回填到失败写入时刻。该状态并非跨进程持久化。

计数和待提交结果按（策略版本，链接）在进程内存中保留，最多 4096 个未完成键。
不再驱逐未完成键后给它新额度；容量满时新键在评分前延后，已有键仍可重试和提交。
源不再返回的未完成键会占位，直到提交、观察到已有记录或进程退出；不能据此宣称永久可用。
进程重启会丢失这份内存状态，可能再授予同样的额度。队列游标的延后次数则仍保存在文件中。

在同一进程、同一链接按正常单飞路径执行的条件下，该情形最多额外评分 2 轮，共 3 轮。
冻结的两健康后端 stage1 用例实测 6 次假模型传输；stage2 用例为 stage1 缓存 1 次加
stage2 的 6 次，共 7 次。**这不是通用物理 HTTP 上限**：后端路由数量、stage2、摘要、
格式兼容降级都会影响请求数；既有单飞等待 120 秒后继续无锁、多个进程和重启也不在该保证内。
纯语义拒绝（所有尝试的后端都给了结论但都不合格）和纯传输失败的行为不变。
摘要的有界语义修复未改变。显式不支持结构化格式时的 schema → JSON object → prompt
兼容降级仍可能产生额外 HTTP 请求，SDK 自身重试仍为零。

单后端拒绝案例由两次请求降至一次；两后端都拒绝的案例由四次降至两次（不含格式兼容
降级）。这只是冻结输入的请求数对照，不是生产 Token/费用节省率。某些原来由主模型
修复后中性的文章现在会走备用模型评分，真实新闻入选与消耗需要按新契约观察。

## 一次物理调用、一条记录

`llm_call_logs` 保留既有列，新增以下可选观测字段，迁移仅追加列：

| 字段 | 口径 |
| --- | --- |
| `request_id` | 不含标题/URL 的随机逻辑请求标识；同一次评分的后端/格式尝试共享它 |
| `attempt_kind` | initial / fallback / repair / direct；repair 目前只用于摘要 |
| `response_mode` | json_schema / json_object / prompt_only |
| `format_retry` | 本次是否是显式格式不兼容后的额外尝试 |
| `usage_status` | complete / partial / unavailable / legacy |

物理请求通过自增 `id` 区分，不把同一个 `request_id` 合并成一条付费调用。
评分缓存、本地中性和本地限流排队超时不新增物理调用记录。元数据由 ContextVar 隔离，
不在并行新闻之间串写；不额外存储标题、模型回复、API key 或原始 URL。

读取响应用量先于读取 choices/content；即便内容损坏，已取得的模型身份、用量与估算
成本仍保留。总 Token 缺失而输入/输出均存在时才取两者之和；显式总量照实保留。
未返回或只返回部分用量不视为免费调用，成本统计同时给出 unknown/partial 调用数。
旧行标记 legacy，不补造历史完整性；成本是配置价格下的估算，不是供应商账单。

## 发布与回退边界

发布方接口的未识别内容行会单独传递为 `source_unrecognized`；已确认广告、删除内容是
明确排除，不冒充采集缺口。刷新分别记录完整、部分完成、失败的源，三者之和等于启用源数。
有缺口、待评分或处理异常时保留可用条目，但不推进全量完成状态；首页采集提示与快照
新鲜度仍分开，不能用新鲜快照证明所有新闻已处理。

本改动改变评分代码指纹，需发布时核对实际新契约；不强设旧指纹复用评分缓存，不回填
或重打历史分数。映射规则、阈值、新闻源、提示词内容和去重策略不变。
数据库变更为追加观测列，旧应用忽略这些列；回退镜像不会抹掉已写入的新契约记录。
由于新契约会使旧评分缓存不再属于当前契约，首次自然采集可能出现冷缓存消耗，不能
仅以发布前后两个总量判断节省或回归。
