# Glance 新闻首页阅读布局

## 改动与边界

首页采用“新闻主列 + 紧凑简报侧栏”；移动端两列连续排列，新闻之后依次是简报、市场与入口，不依赖底部切列按钮。指数位于次级折叠区；雷达、模型质量使用既有独立页面；原首页服务监控移至既有运维页。

应用与 Glance 配置必须配套。仅发布应用不会改变 Glance 的模块排列，不能称为首页改版完成。

- 新闻：`/glance-sse` 沿用原 worker 快照、入选/去重/排序/源限额与时间窗；取消内部固定高度滚动，标题不再额外截短；来源与“收录”时间优先，分数仅作阅读优先级。方向、入选依据及规则池默认折叠。模型/发布方本已截短的标题不会被补写。
- 简报：仍为 `/briefing-card?min_score=7&limit=12`。默认展示既有顺序前三个主题；展开保留完整旧渲染及 Quant 背景、来源限制、数据时间。不把 `limit=12` 改成 3，不触发新模型调用。完整 `/briefing?format=html` 不变。
- 行情：`/quotes?view=reading` 只折叠同一行情缓存，普通 `/quotes` 不变；缺缓存保留未知/等待状态，不伪造正常。
- 不更改评分、提示词、阈值、映射、数据库或历史记录；不降低认证要求。

## 准备配置（离线生成，不安装）

使用已有 Glance 配置的本地副本，指定一个尚不存在的输出文件：

```sh
python scripts/prepare_glance_reading.py <本地配置副本.yml> <新的候选配置.yml>
```

该命令只生成候选文件，不连接服务器、不覆盖输入、不重启服务。配置可能含主机地址或密钥：输入与候选都应留在私有目录，不提交 Git、不贴入 PR。

变换保留主题、首页名称/路径、原链接与缓存周期；保持两个固定 worker 快照请求；除迁入首页监控外不改其它页面内容。只有已确认目标页保有同类研究展示，才移除首页默认雷达/质量副本；未知模块、自定义数据参数或缺失目标页要求人工查看，不静默丢弃。

本改动使用 Glance 既有 full/small 列及 widget `css-class`，不要求增加挂载、Docker socket 或新服务。[Glance 配置说明](https://github.com/glanceapp/glance/blob/v0.8.4/docs/configuration.md)。原有 `allow-potentially-dangerous-html` 配置不扩大到新来源；本次输出不添加脚本。

### 手机布局与备案条修复

生成器将同目录 `glance_reading_mobile.css` 作为版本化 `<style>` 幂等追加到既有 `document.head`；已有 head、主题与 `branding.custom-footer` 内容不改写。需将生成器与 CSS 一同使用。相同版本重复生成不叠加；发现同名但内容不同的样式会停止，避免静默覆盖用户修改。

- 仅在含 `ai-home-news` 标记的首页、宽度不超过 1190px 时生效；桌面两栏和其它页面不变。
- 首页两列均可见、连续滚动；隐藏冗余切列按钮，保留 Glance 原生菜单、返回顶部及导航预留空间。
- 对同时含工信部与公安备案链接的 custom-footer 外层 DIV，仅在上述首页手机范围取消固定定位和高层级；备案文本、链接与桌面原表现保留。不隐藏备案、不对所有页脚批量改样式。
- 不新增请求、脚本、端点或数据计算。只有配置生成器、CSS 与说明/测试有变化；这个补丁本身不需要新应用镜像，合并也不会使现网自动生效。安装候选配置、使 Glance 生效仍须明确的操作窗口。

原因：Glance v0.8.4 的手机默认是“选一列显示”，并非顺排；固定备案条可能覆盖底部导航。对隐藏控件设置 `open` 不能算用户交互验收。

### 可选的首页阅读样式（只生成候选）

```sh
python scripts/prepare_glance_reading.py <本地配置副本.yml> <新的候选配置.yml> --reading-skin
```

`--reading-skin` 将 `glance_reading_skin.css` 作为版本化 `ai-filter-reading-skin-v1` 样式加入候选。默认命令仍只做原有布局；已经加入的阅读样式在重复生成时保留且不叠加。样式内容或标记冲突会停止，不覆盖用户修改。生成器、手机 CSS 与阅读样式 CSS 应来自同一提交。

- 采用首页限定的浅灰背景、白色面板、深色标题和蓝色导航；缩小分数的视觉权重，明确标题、来源与收录时间的层级。只改呈现，不改文本、新闻顺序、分数、请求参数或缓存。
- 所有选择器均限定到含 `ai-home-news` 的首页。已有主题配置、其他页面配置、head 内容及备案 HTML 保留；首页使用固定浅色阅读外观，其他页面仍用原主题。整个首页标记尚未加载时不应用该皮肤。
- 规则池、方向/依据、简报与市场仍按原行为折叠；手机顺排、原生菜单、返回顶部、底部预留空间继续由既有手机样式保障。首页备案条在桌面也恢复为文档流，文本与链接不删。
- 不增加脚本、字体下载、外部样式请求或服务；不触及应用运行代码、评分契约、数据库或历史数据。本项仅需另行批准后安装 Glance 候选使其生效，不需要新应用镜像。
- 输入/输出都可能含凭据，仍保持私有；候选独占创建、权限 0600，不覆盖原文件。恢复时使用安装前备份的 Glance 配置，不操作应用回退或数据库。

验证应使用同一批冻结内容比较前后，覆盖 320/390px、1190/1191px 断点及桌面；确认新闻文字/链接/默认折叠一致、菜单和备案可点击、其他页面样式不变。冻结内容首屏卡片数量仅是该批样本的观察，不是对任意长标题的数量承诺。离线样式验证不替代安装后的真实页面验收。

### 可选的机构式新闻与研究首页（只生成候选）

```sh
python scripts/prepare_glance_reading.py <本地配置副本.yml> <新的候选配置.yml> --institutional-style
```

`--institutional-style` 为独立选择，不能与 `--reading-skin` 同时使用。未选择它时仍执行原有布局；当前版本生成的机构式候选在默认命令或重复选择该参数时保持不变。这个步骤仅生成本地配置，未安装、未发布、未重启或重载服务。

- 在首页新闻主列前插入一个静态 HTML 抬头，使用 AI Filter 自有字标、NEWS & RESEARCH、主要导航与“新闻与研究”标题。导航沿用全部已有页面的名称、顺序和路径，包括研究、质量与运维；遵循 `server.base-url`，没有 `slug` 时按 Glance v0.8.4 的名称规则生成路径。名称与链接按 HTML 转义，不添加演示新闻、统计数字、外部图片、字体请求或脚本。页面名称或路径中的未解析环境变量会停止生成；`server.base-url` 占位符则原样保留到 HTML 中，交由 Glance 按原规则解析。新抬头拒绝以斜杠开头、包含反斜杠或独立 `.` / `..` 段的路径，避免链接跳出既有站点或子目录。
- `glance_institutional.css` 以 `ai-filter-institutional-v1` 加入既有 head，仅在包含 `ai-home-institutional-masthead` 的首页生效；首页原桌面页眉由样式替换，其他页面仍使用原导航与主题。机构式抬头中的导航和原生手机菜单均保留目的地。
- Glance v0.8.4 的 HTML widget 直接渲染 `source`，不生成带 `css-class` 的外壳，因此该标记直接写入 `source` 的最外层 `div`。仅在 widget 的 `css-class` 中带标记的旧候选会被拒绝；从安装前的配置备份重新生成，不自动替换旧抬头。离线验收也应直接渲染 HTML `source`，不能补造 Glance 未输出的包装。
- 新闻、简报与行情继续使用原阅读布局的固定请求和缓存；原有认证、扩展请求凭据、主题设置、head HTML 和备案页脚保留。原始布局的首页监控仍按既有规则迁到运维页；已经使用阅读布局的配置不再次搬移。
- 若已经安装上一版 `--reading-skin`，保留其完整样式字节，在它后面追加机构式样式，既有手机样式仍保持最后一个区块。生成器、辅助模块及三份 CSS 应来自同一提交。
- 只识别并重新插入生成器的完整已知抬头。抬头或样式被修改、标记重复、出现未知版本、部分缺失或标记出现在其他页面时停止；未知首页 HTML 也不会被静默丢弃。冲突不会修改输入，也不会创建或覆盖候选。输出仍采用独占创建和 0600 权限。

验收应比较最小配置和已有阅读皮肤两种输入，确认重复生成一致、其他页面不变；用相同内容检查桌面、320/390px 手机及 1190/1191px 断点的新闻顺序、展开收起、全部导航目的地与页尾备案链接。安装前保留原 Glance 配置；恢复时使用该备份，不需要数据库操作或新的应用镜像。离线候选与预览不代表生产已经生效。

### 四个 Glance 主板块的统一外观（只生成候选）

```sh
python scripts/prepare_glance_site.py <本地配置副本.yml> <新的候选配置.yml>
```

新命令明确选择四页公共外观：新闻首页、`events`、`quality`、`ops` 共用字标、导航、字体、颜色及基础卡片样式。页面名称、路径及导航顺序沿用配置，每页只选中自己的导航项；其他额外页面不添加外壳。首页的重点新闻、分栏与侧栏布局仍限定在首页，不把整份首页 CSS 全局放开。

- 可输入原始已知布局、阅读布局、已知阅读皮肤或已知机构式首页配置；生成器先复用原 v1 规则归一，再增加公共外壳。原始首页监控仍按既有规则迁至运维页。已有首页候选只在显式 HTML 根包装追加 `ai-site-shell`，首页抬头内容和 `ai-home-institutional-masthead` 标记保持原样。
- 三个内页各前置一个专用 `full` 抬头列，HTML `source` 自带 `ai-site-shell ai-site-page-events`（或 `quality` / `ops`）标记。原列及其中全部组件保持原顺序和配置值，包括运维页原来的 `small + full` 顺序。页面已有列数若无法再容纳抬头列，会停止生成；普通宽度最多三列、`slim` 最多两列，其中 `full` 列最多两列。
- 公共样式来自 `glance_institutional_site.css`，以独立的 `ai-filter-institutional-site-v1` 区块追加到既有 head 末尾。原首页 CSS、阅读皮肤和手机区块逐字保留；认证、组件 URL、缓存周期、主题配置、用户 HTML 与备案页脚不改写。此时公共样式是最后一个区块，旧首页样式仍留在原位置。
- 重复生成时，只剥离完整已知的公共样式与四页抬头，再交由原 v1 逻辑校验，因此不会重复叠加。已修改、未知、重复、移位或不完整的外壳/样式会停止；不会覆盖用户修改。新候选仍为独占创建、0600 权限；不修改输入，不安装、不连接生产、不重载服务。
- 站点候选必须继续使用新命令处理；旧 `prepare_glance_reading.py` 不识别新增外壳和样式，会拒绝该候选。不要为兼容而删除未知标记或放宽旧 v1 校验；回退使用安装前的完整 Glance 配置备份。

验收须直接渲染真实 Glance HTML，检查四页各自的标题、导航选中态、桌面及 320/390px 页面、研究/质量/运维内容与原列顺序，确认首页重点新闻布局不变、额外页面不受影响。`/dashboard/events`、`/dashboard` 等独立应用详情页不属于本次 Glance 配置范围；其页面模板和服务不由此命令修改。

## 配套发布与恢复（操作，非自动执行）

应用 PR 通过现有 CI 后，按现有发布流程、明确授权的窗口发布。现场比对配置差异后安装配套 Glance 候选，并按现有宿主操作方式使配置生效；本工具不替代发布或主机操作入口。

保留应用旧镜像引用和原 Glance 配置作为配套恢复依据；只回退镜像不一定恢复首页排列。没有数据库变更，不做数据库回写或历史重打分。

等待既有 worker 快照及 Glance 缓存正常更新后，再验收真实首页；旧快照尚未更新不通过连续补版本解决。

## 完成标准

- 在真实首页检查，而非只检查后台：桌面 1440×900 首屏至少三个新闻标题；390×844 手机首屏至少一张完整卡片，目标两张；极长标题保完整优先。
- 320 像素宽度无横向溢出、无新闻区内部滚动；标题/来源/收录含义清楚，链接可打开。
- 同一冻结输入的新闻身份、数量、顺序、分数保持一致；标题仍做原有文本清洗、转义和安全链接处理。
- 原生折叠可用；主题示例及免责声明均保留；完整简报与市场/研究/运维入口可达，认证不放宽。
- 手机 320/390 两档必须实际滚动到简报、市场并点击展开/收起；导航中心点不能命中备案遮罩。菜单可打开，页尾备案可见且可点击，不能只断言 DOM 中存在元素或 `details.open=true`。
- 空结果与读取失败不混为同一正常状态；页面读取保持原快照/缓存方式，无新模型调用或现场巡检。
- 同尺寸前后截图来自实际渲染。离线截图只能证明布局，CI 绿只能证明测试，二者都不替代生产浏览器验收。

验收通过即结束，不因这一展示改动声称模型准确率、映射正确性或投资效果提高。
